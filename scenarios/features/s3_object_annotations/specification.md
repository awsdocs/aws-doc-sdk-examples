# Amazon S3 Object Annotations Specification

This document contains a draft proposal for a Code Example for *Amazon S3 Object Annotations Scenario*, generated by the Code Examples SpecGen AI tool. The specifications describe a code example scenario that demonstrates the S3 object annotations feature, which allows developers to attach rich, structured metadata payloads to S3 objects without modifying the objects themselves.

S3 annotations complement existing metadata mechanisms (system-defined metadata, user-defined metadata, and object tags) at a fundamentally different scale and flexibility. With annotations, you can attach up to 1,000 named annotations per object, each up to 1 MiB in size, in flexible formats like JSON, XML, and YAML. Common use cases include storing machine learning inference results, AI-generated embeddings, content moderation labels, document classification output, data lineage and audit trails, compliance records such as PII flags or retention policies, and ETL pipeline status.

This scenario walks through the complete lifecycle of S3 object annotations: creating annotations on an object, retrieving and listing them, updating an existing annotation, filtering annotations by prefix, and cleaning up by deleting annotations and resources.

### Resources

- Amazon S3 bucket (created in the scenario)
- One test object uploaded to the bucket
- Multiple annotations attached to the test object during the scenario

No additional AWS resources (CloudFormation stacks, IAM roles, etc.) are required beyond the S3 bucket and object.

### API Actions Used

- [CreateBucket](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CreateBucket.html) - Create an S3 bucket for the scenario.
- [PutObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html) - Upload a test object to the bucket.
- [PutObjectAnnotation](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObjectAnnotation.html) - Attach a named annotation payload (1 byte to 1 MiB) to an object.
  - Required parameters: `Bucket`, `Key`, `AnnotationName` (1-512 bytes), `AnnotationPayload` (the annotation body).
  - Optional parameters: `VersionId`, `ObjectIfMatch` (conditional write using object ETag), `ChecksumAlgorithm`, various checksum headers, `ExpectedBucketOwner`, `RequestPayer`.
  - Response: Returns `ETag` of the annotation, `ObjectVersionId`, `Key`, `AnnotationName`, `ServerSideEncryption`, and checksum headers.
- [GetObjectAnnotation](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObjectAnnotation.html) - Retrieve a specific annotation by name from an object.
  - Required parameters: `Bucket`, `Key`, `AnnotationName`.
  - Optional parameters: `VersionId`, `ChecksumMode` (set to `ENABLED` for client-side validation), `ExpectedBucketOwner`, `RequestPayer`.
  - Response: Returns the `AnnotationPayload` (binary), `ETag`, `LastModified`, `ContentLength`, `ObjectVersionId`, `ServerSideEncryption`, `ReplicationStatus`, and checksum headers.
- [ListObjectAnnotations](https://docs.aws.amazon.com/AmazonS3/latest/API/API_ListObjectAnnotations.html) - List all annotations attached to an object, with optional prefix filtering and pagination.
  - Required parameters: `Bucket`, `Key`.
  - Optional parameters: `AnnotationPrefix` (filter by name prefix), `MaxAnnotationResults` (1-1000), `ContinuationToken`, `VersionId`, `ExpectedBucketOwner`, `RequestPayer`.
  - Response: Returns `Annotations` (array of `AnnotationEntry` items, each containing `AnnotationName`, `Size`, `ETag`, `LastModified`, `ChecksumAlgorithm`, `ReplicationStatus`), `Bucket`, `Key`, `AnnotationCount`, `AnnotationPrefix`, `MaxAnnotationResults`, `ContinuationToken`, `NextContinuationToken`.
- [DeleteObjectAnnotation](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObjectAnnotation.html) - Permanently remove a specific annotation by name from an object.
  - Required parameters: `Bucket`, `Key`, `AnnotationName`.
  - Optional parameters: `VersionId`, `ObjectIfMatch` (conditional delete using object ETag), `ExpectedBucketOwner`, `RequestPayer`.
  - Response: Returns HTTP 204 on success, `ObjectVersionId`, `RequestCharged`.
  - **Important**: Annotation deletion is permanent and irreversible. Annotations are not independently versioned, so there is no delete marker or way to recover a deleted annotation.
- [DeleteObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObject.html) - Delete the test object during cleanup.
- [DeleteBucket](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteBucket.html) - Delete the S3 bucket during cleanup.
- [ListBuckets](https://docs.aws.amazon.com/AmazonS3/latest/API/API_ListBuckets.html) - Used in the Hello S3 example.

## Scenario

This scenario demonstrates the full lifecycle of S3 object annotations. The user creates a bucket, uploads a test object, attaches multiple annotations with structured JSON payloads, retrieves and lists them, updates an annotation, filters by prefix, and then cleans up all resources.

### Setup

1. **Create an S3 bucket**: Create a new general purpose S3 bucket with a unique name (e.g., using a UUID suffix). Display the bucket name.
2. **Upload a test object**: Upload a small text object (e.g., `sample-document.txt` with content like "This is a sample document for demonstrating S3 object annotations.") to the bucket using `PutObject`. Display the object key.

### Add annotations to the object

3. **Add a classification annotation**: Use `PutObjectAnnotation` to attach an annotation named `classification` with a JSON payload such as:
   ```
   {"category": "financial", "subcategory": "quarterly-report", "confidence": 0.95, "classified_by": "ml-pipeline-v2"}
   ```
   Display the annotation name and the returned ETag.

4. **Add a compliance annotation**: Use `PutObjectAnnotation` to attach an annotation named `compliance.pii-scan` with a JSON payload such as:
   ```
   {"contains_pii": false, "scan_date": "2024-10-13", "scanner_version": "3.1.0", "policy": "GDPR"}
   ```
   This demonstrates the use of periods in annotation names to create a logical namespace.

5. **Add a processing status annotation**: Use `PutObjectAnnotation` to attach an annotation named `compliance.retention` with a JSON payload such as:
   ```
   {"retention_days": 365, "retention_policy": "regulatory", "applied_date": "2024-10-13"}
   ```
   This creates a second annotation under the `compliance.` prefix to demonstrate prefix filtering later.

### Retrieve and inspect annotations

6. **Get a specific annotation**: Use `GetObjectAnnotation` to retrieve the `classification` annotation by name. Display the returned annotation payload, ETag, last modified date, and content length. This demonstrates how to retrieve a single annotation when you know its name.

7. **List all annotations**: Use `ListObjectAnnotations` to list all annotations on the object. Display each annotation's name, size, ETag, and last modified date. Verify that all three annotations appear in the list.

8. **List annotations with prefix filter**: Use `ListObjectAnnotations` with the `AnnotationPrefix` parameter set to `compliance.` to filter the results. Display only the matching annotations. This demonstrates how prefix filtering can be used to query a logical group of annotations. Verify that only the two compliance annotations are returned.

### Update an existing annotation

9. **Update the classification annotation**: Use `PutObjectAnnotation` with the same annotation name `classification` but with an updated payload:
   ```
   {"category": "financial", "subcategory": "quarterly-report", "confidence": 0.98, "classified_by": "ml-pipeline-v3", "review_status": "approved"}
   ```
   Explain to the user that calling `PutObjectAnnotation` with an existing annotation name overwrites the previous value.

10. **Verify the update**: Use `GetObjectAnnotation` to retrieve the `classification` annotation again. Display the updated payload and confirm the new ETag differs from the original. Note that the annotation ETag has changed, reflecting the updated content.

### Delete annotations and verify removal

11. **Delete an annotation**: Use `DeleteObjectAnnotation` to remove the `compliance.pii-scan` annotation. Display confirmation of the deletion. Remind the user that annotation deletion is permanent and irreversible.

12. **Verify deletion**: Use `ListObjectAnnotations` to list remaining annotations. Verify that only two annotations remain (`classification` and `compliance.retention`). Display the updated list.

### Cleanup

13. **Delete remaining annotations**: Use `DeleteObjectAnnotation` to remove all remaining annotations (`classification` and `compliance.retention`).
14. **Delete the test object**: Use `DeleteObject` to delete the test object from the bucket.
15. **Delete the bucket**: Use `DeleteBucket` to delete the S3 bucket.
16. Confirm to the user that all resources have been cleaned up.

### Outcome

After running this scenario, the user will understand how to:
- Attach structured metadata (annotations) to S3 objects without re-uploading the object.
- Retrieve specific annotations by name.
- List all annotations on an object, with optional prefix filtering for logical grouping.
- Update annotations by overwriting them with a new payload.
- Permanently delete annotations.
- Understand key properties: annotations inherit the parent object's encryption, can be up to 1 MiB each, up to 1,000 per object, and support versioned objects.
- Understand the difference between annotations and object tags (annotations support larger payloads, structured data formats, and up to 1,000 per object vs. 10 tags).

## Errors

SDK Code examples include basic exception handling for each action used. The table below describes an appropriate exception which will be handled in the code for each service action.

| Action | Error | Handling |
|-|-|-|
| `CreateBucket` | `BucketAlreadyExists` | Notify the user the bucket name is taken and suggest using a unique suffix. |
| `PutObject` | `NoSuchBucket` | Verify the bucket was created successfully before uploading. |
| `PutObjectAnnotation` | `NoSuchKey` | Verify the object exists before attempting to attach an annotation. |
| `GetObjectAnnotation` | `NoSuchAnnotation` | Notify the user that the specified annotation does not exist on the object (HTTP 404). |
| `ListObjectAnnotations` | `NoSuchKey` | Verify the object key is correct and the object exists in the bucket. |
| `DeleteObjectAnnotation` | `NoSuchBucket` | Verify the bucket exists before attempting to delete an annotation. |
| `DeleteObject` | `NoSuchKey` | Log a warning and continue cleanup; the object may have already been deleted. |
| `DeleteBucket` | `BucketNotEmpty` | Ensure all objects and annotations are deleted before attempting to delete the bucket. |
