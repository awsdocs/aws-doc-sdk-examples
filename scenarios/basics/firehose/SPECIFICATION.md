## Hello Amazon Data Firehose

The Hello example uses the **ListDeliveryStreams** API action to verify that the Amazon Data Firehose client is correctly configured and can communicate with the service.

### Operation: ListDeliveryStreams

`ListDeliveryStreams` lists Firehose streams in the caller's account in alphabetical order. It requires no input parameters (all parameters are optional) and returns a list of stream names plus a boolean indicating whether more streams are available.

**Request parameters (all optional):**

| Parameter | Type | Description |
|---|---|---|
| `DeliveryStreamType` | String | Filter by stream type. Valid values: `DirectPut`, `KinesisStreamAsSource`, `MSKAsSource`, `DatabaseAsSource`. If omitted, streams of all types are returned. |
| `ExclusiveStartDeliveryStreamName` | String | The name of the stream to start after (for pagination). Min length 1, max length 64. Pattern: `[a-zA-Z0-9_.-]+`. |
| `Limit` | Integer | Maximum number of streams to return. Default: 10. Valid range: 1–10000. |

**Response structure:**

| Field | Type | Description |
|---|---|---|
| `DeliveryStreamNames` | Array of strings | The names of the Firehose streams. Each name has min length 1, max length 64, pattern `[a-zA-Z0-9_.-]+`. |
| `HasMoreDeliveryStreams` | Boolean | `true` if there are more streams available beyond those returned. |

### Program logic

1. Create an Amazon Data Firehose client with default configuration.
2. Call `ListDeliveryStreams` with no parameters (or with `Limit` set to a small number such as 10).
3. Print a greeting line, for example: `Hello, Amazon Data Firehose! Here are your delivery streams:`
4. If `DeliveryStreamNames` is non-empty, iterate through and print each stream name.
5. If `DeliveryStreamNames` is empty, print a message such as: `No delivery streams found in this account/region.`
6. If `HasMoreDeliveryStreams` is `true`, print a note indicating additional streams exist.

### Expected output

When the account has delivery streams:

```
Hello, Amazon Data Firehose! Here are your delivery streams:
  - my-s3-delivery-stream
  - web-log-firehose
  - analytics-pipeline-stream
```

When the account has no delivery streams:

```
Hello, Amazon Data Firehose! Here are your delivery streams:
  No delivery streams found in this account/region.
```

**Test structure:**

The Hello program should be structured as a callable function (e.g., `hello_firehose(firehose_client)`) that accepts a Firehose client, calls `ListDeliveryStreams`, and returns or prints the stream names. This allows the test to inject a stubbed client.

**Required test cases:**

1. **`test_hello_firehose_success_with_streams`** — Stub `ListDeliveryStreams` to return a response with two or more stream names and `HasMoreDeliveryStreams: false`. Call the hello function. Assert the function completes successfully and returns/prints the expected stream names.

2. **`test_hello_firehose_success_empty`** — Stub `ListDeliveryStreams` to return a response with an empty `DeliveryStreamNames` list and `HasMoreDeliveryStreams: false`. Call the hello function. Assert the function completes successfully and handles the empty result gracefully.

3. **`test_hello_firehose_service_unavailable_error`** — Use `add_client_error` to stub `ListDeliveryStreams` with a `ServiceUnavailableException` error. Call the hello function. Assert that the specific `ServiceUnavailableException` (accessed via `ClientError` with error code `ServiceUnavailableException`) is raised or handled.

**Test pattern (pseudocode):**

```
For each test:
  1. Create a Firehose client (e.g., via boto3.client('firehose', region_name='us-east-1'))
```

**Constraints:**

* No real AWS calls — every API call must be stubbed.
